“桥跨”评定单元差距分析与建模方案

现行系统（无跨层）→ 新标准 JTG/T 5230—2026（构件→桥跨→全桥）｜ 编制日期：2026-10-01

结论：判断正确——现行系统的对象树没有“桥跨”层，而桥跨是新标准承上启下的核心评定单元（BSCI 指数、跨等级、全桥合成的载体），不是可绕过的概念。 好在差距是“缺一层”，不是“换骨架”：现有评定单元（主桥/引桥）、三分层、部件、构件与新标准的评定单元、结构层（γ）、部件（ω）、构件可逐级对齐；且构件编码已隐含跨号（R-1-1#桥面铺装 中段 1~9），历史数据可程序化迁移。评分引擎本就要按新标准重写，树结构改造可与引擎重构同批立项。

二、现行系统的层级解剖

现行 BiObject 树（以宜都长江大桥为例，json/宜都长江大桥构件树.json）： 桥梁 └─ 评定单元（主桥（钢桁梁悬索桥）/ 左幅引桥（连续刚构）/ 右幅引桥…） ←≈ 新标准 3.1.2 评定单元，概念可对齐 ├─ 上部结构 / 下部结构 / 桥面系 / 附属设施 ←≈ 新标准 γ 结构层，可对齐 │ └─ 部件（BiObject + weight） ←≈ 新标准 ω 部件，可对齐 │ └─ 构件（Component，code 如 "R-1-1#桥面铺装"） ← 2.1.4 构件，可对齐 ✗ 桥跨层缺失——一跨的梁、支承墩、桥面系段无法归属到同一评定载体
证据点说明
树的第二层是“评定单元”而非“跨”“左幅引桥（连续刚构）”含多个跨，但在树中是一个节点；上部承重构件下所有跨的梁平铺混放
Component 无跨号字段Component.java 仅 id/code/name/biObjectId 等，无 spanNo；跨信息只隐含在 code 文本中（R-<1~9>-<序>#类型，R=幅、中段=跨号、尾段=跨内序号，见 bi_20250406.sql 构件种子 50 条均为此格式）
BsEvaluation 是“桥幅”级评定BiEvaluationServiceImpl.calculateBiEvaluation() 从 rootObjectId 直接取三分层加权——一次计算就是整幅桥，无跨粒度
病害无跨定位Disease → Component → BiObject(部件)，链路上无跨节点，无法直接回答“第 3 跨技术状况”

三、三个建模难点（标准留了出口）

难点标准依据与处理建议
① 共用墩归属：连续梁中墩支承两跨，挂哪一跨？新标准未逐一规定，参照 6.1.2 的归属原则（节段连接处缺损计入靠桥墩侧节段），建议建模规则：墩台按伸缩缝/支承关系归入“以该墩为固定端或起始端”的跨，并在系统中支持人工改挂；同一墩多处缺损可按规则复制计入相关跨（取最不利）
② 全桥性构件：悬索桥主缆/索塔/锚碇、斜拉桥索塔，天然不分跨单跨悬索桥（如宜都主桥）：整桥即 1 个桥跨，无歧义；多跨悬索/斜拉桥：依 3.1.8 制定专用评定标准，将全桥性构件单列“全桥层”或锚固跨——系统建模时保留“跨内构件 + 全桥性构件”两类标记即可
③ 桥面系纵向分段：铺装/伸缩缝横贯全桥附录 B 每跨参数表均含桥面系（γ=0.10~0.15），建模上按“本跨范围内”切分；伸缩缝本身是两跨分界，建议伸缩缝归入较小跨号（与墩台规则一致），避免重复计入

四、改造方案比选

方案做法优点代价与风险
A. 树上加跨层
推荐		评定单元下新增桥跨节点（BiObject 增加 nodeType=SPAN + spanNo），跨下按附录 B 生成“桥面系/上部/下部/附属”四层部件再挂构件；桥跨节点直接绑定桥型与 γ/ω 参数业务对象自然表达（检查按跨分派、病害按跨定位）；BSCI/跨等级/全桥合成有直接载体；附录 B 参数表可 1:1 挂到跨节点树维护 UI 需支持“按跨批量生成”；共用墩/全桥性构件需归属规则；存量构件需重新挂接（可程序化）
B. 跨号属性化
备选		不加层；Component/BiObject 增加 spanNo 字段，病害经构件 spanNo 聚合成“虚拟跨”参与计算树结构不动，改动最小；历史数据可从 code 解析直接回填跨的“部件”是虚拟分组，桥面系等均布部件的 ω 需按跨复制；树 UI 无法直观展示跨；全桥性构件标记别扭
C. 评定单元即桥跨
过渡		单跨桥/等跨简支梁桥：现有评定单元直接视为一个桥跨，先跑通新引擎；多跨复杂桥后续再拆立即可用，过渡期最短多跨长桥按每跨建评定单元会让树爆炸（30 跨=30 套部件复制）；只适合跨数少的桥和过渡验证
推荐组合：A 为主 + B 为迁移手段 + C 为过渡验证。 评分引擎反正要按新标准重写（此前已确认），树的跨层改造与引擎重构同批实施；迁移时用方案 B 的解析逻辑把存量构件 code 中的跨号提取出来，再挂接到方案 A 的跨层结构上。

五、历史数据迁移路径（利用现有跨号编码）

步骤工作项说明
1构件编码规则确认现有 code 格式 幅-跨-序#类型（50 条种子均为 R-<跨>-<序>#桥面铺装）；需与录入人员确认各桥是否存在变体（如墩用 L-3、Z-3 等前缀），输出编码解析规则表
2解析回填 spanNo按规则批量解析存量 Component.code → 写入 spanNo 字段；解析失败的进入人工确认清单（预计少数）
3生成跨节点并重挂按“评定单元 × 跨数”批量生成桥跨节点（含附录 B 桥型参数绑定）；构件按 spanNo 重挂到跨下对应部件；共用墩/全桥性构件按第三节规则分配并支持人工调整
4评定实体改造新增 BiSpanEvaluation（跨评定：BSCI、跨等级、最差构件清单）；BiEvaluation 升级为全桥汇总（多跨一致性判断 + 插值 BCI，公式 3.4.2/3.4.3）；计算入口从“rootObjectId 三分层遍历”改为“评定单元 → 跨遍历”
5界面与报告树管理、病害录入、评定任务按跨过滤定位；报告增加“分跨评定结果表”（新标准附录 C 要求）

六、结论

“桥跨”不是命名差异，而是新标准的评定主轴——没有跨层，BSCI 指数、跨等级、全桥插值合成（3.3/3.4 节）都没有计算载体，病害记录也无法按新标准组织。 但差距可控：现有“评定单元→三分层→部件→构件”骨架与新标准的“评定单元→跨→结构层（γ）→部件（ω）→构件”逐级可对齐，缺的只是中间一层； 构件编码已隐含跨号，迁移可程序化；特殊结构桥还有 3.1.8 专用评定标准出口。 建议按“方案 A 建模 + 方案 B 解析迁移 + 方案 C 过渡验证”组合推进，与评分引擎重写（P0）同批立项。
