一、方案A总体设计理念

方案A的核心判断是：「桥跨」不是给树加一个命名层，而是把它做成新标准评定链的真正载体。新标准的指数（BSCI）、等级（跨等级）、全桥合成（多跨一致性+插值）都以桥跨为单位，所以桥跨节点必须同时承担三件事：

  1. 结构归属——把本跨的上部构件、支承墩台及基础、本跨桥面系段、附属构造段收拢到同一节点下；
  2. 参数承载——直接绑定该桥型的 γ（结构部位影响系数）与 ω（部件权重，0~100 整数）；
  3. 评定单元——成为 BSCI 指数计算的天然入口，替代现在的"rootObjectId 三分层遍历"。
推荐落点（一句话）
在评定单元节点（现树第二层的"主桥/左幅引桥"）与结构层节点（现树第三层的"上部结构/下部结构/桥面系/附属构造"）之间，插入一层 nodeType = SPAN 的桥跨节点，携带 spanNo（跨号）、bridgeType（桥型，用于查附录B参数）、gamma（结构层γ）。结构层节点作为跨节点的子节点，其下部件、构件结构不变。

选择"插中间层"而非"属性化（方案B）"的理由：新标准附录B的 γ/ω 参数表天然按"桥面系/上部/下部/附属"四个结构层组织，且 每跨一套。把结构层挂到桥跨节点下，γ 参数一次绑定、跨内复用，权重 ω 继续落在部件层——这与新标准的数学结构完全同构，是改动最小、语义最清晰的建模。

二、数据模型改造（DDL 与字段设计）

2.1 复用现有 bi_object 表，不建新表

现有 BiObject extends TreeEntity 已具备 parentId / ancestors / name / weight / standardWeight / count / props，桥跨节点可以直接复用该表，通过新增列 + 复用 props 承载新语义，避免引入新的树表导致全链路（CRUD、树查询、导入导出、前端组件）都要改。

-- 方案A 最小改动 DDL（在 bi_object 表上加 3 列 + 1 索引）
ALTER TABLE `bi_object`
  ADD COLUMN `node_type`   varchar(20)  DEFAULT NULL COMMENT '节点类型：ROOT/UNIT/SPAN/LAYER/PART/LEAF',
  ADD COLUMN `span_no`     int          DEFAULT NULL COMMENT '跨号（仅 SPAN 节点有效，从1起）',
  ADD COLUMN `bridge_type` varchar(50)  DEFAULT NULL COMMENT '桥型代码（附录B：B01~B21，共21类），SPAN 节点绑定',
  ADD COLUMN `props_json`  text         DEFAULT NULL COMMENT 'JSON：γ系数/ω覆盖/共用墩标记/全桥性构件标记等扩展参数';

ALTER TABLE `bi_object` ADD INDEX idx_object_span (parent_id, node_type, span_no);
为什么 props 已存在还要加 props_json？ 现有 props 是 varchar 且已被"附加属性"占用语义，改成结构化 JSON 列更稳妥；若确认 props 当前无强约束，也可直接复用 props 存 JSON，省一列。这里给出双选项，落地时按 props 实际使用情况二选一。

2.2 Component 表：不加跨号列（构件挂跨走关系表）

早期方案曾在 bi_component 上加 span_id/span_no 两列。 该设计已废弃：构件可能属于多个跨（共用构件），单值 span_id 表达不了多跨，且会在 bi_component 与关系表之间制造「跨归属」的第二事实来源，违反单一事实来源原则。

构件挂跨的唯一载体是关系表 bi_span_component_part(component_id, span_id, part_id, is_shared)（完整 DDL 见实施手册 §3.3b，落地规则见本文 §5「三大建模难点」），bi_component 只保留现有 bi_object_id（构件→部件，一对一）不动。跨号通过关系表 span_id → bi_object.span_no 取得，无需在构件表冗余。

2.3 新增跨评定实体 BiSpanEvaluation

现有 BiEvaluation 是"桥幅级"一次算完，字段按三分层（superstructure/substructure/deckSystem）。新标准需要"先跨后桥"，因此新增跨评定实体，BiEvaluation 升级为全桥汇总：

// 新增：跨评定结果（对应新标准 3.3 桥跨评定，BSCI）
public class BiSpanEvaluation extends BaseEntity {
    private Long       id;
    private Long       taskId;           // 所属检测任务
    private Long       spanId;           // 桥跨节点ID（bi_object 中 node_type=SPAN）
    private Integer    spanNo;           // 跨号
    private String     bridgeType;       // 桥型代码（附录B）
    private BigDecimal bsci;             // 桥跨技术状况指数 BSCI = 100 - Σ(CI×ω×γ)/5
    private Integer    level;            // 跨等级（1~5 类）
    private Integer    worstComponentLevel; // 跨内最差构件标度（单项控制判定用）
    private String     controlBasis;     // 若触发单项控制指标，记录依据条款
    // 三个维度标度（可选保留，便于追溯）
    private Integer    ediMax;           // 跨内最大耐久性缺损标度
    private Integer    efiMax;           // 跨内最大功能状况标度
    private Integer    eaiMax;           // 跨内最大影响状况标度
}
BiEvaluation 的升级方向（全桥汇总，对应新标准 3.4）
  • 保留现有字段做兼容，新增：spanCount（跨数）、bridgeType（全桥统一桥型）、bcI（全桥指数 BCI）；
  • level 语义从"整体等级"改为"全桥等级"，计算逻辑由三分层加权改为多跨一致性判断 + 最差跨插值（公式 3.4.2 / 3.4.3）；
  • 旧的 superstructureLevel / substructureLevel / deckSystemLevel 在过渡期保留但标记 deprecated，新引擎不再写这三个字段。

三、树结构对比与节点类型体系

改造前（现行 4 层）
桥梁（根 ROOT） └─ 评定单元（主桥/左幅引桥） ← UNIT ├─ 上部结构 ← LAYER │ └─ 部件（主梁/横向联系…） │ └─ 构件（R-1-1#…） ├─ 下部结构 ← LAYER │ └─ 部件（桥墩/桥台…） └─ 桥面系 ← LAYER └─ 部件（桥面铺装/伸缩缝…）
改造后（新增 SPAN 层）
桥梁（根 ROOT） └─ 评定单元（主桥/左幅引桥） ← UNIT ├─ 桥跨 1 SPAN (spanNo=1, bridgeType=B03) │ ├─ 桥面系 LAYER γ=0.15 ← γ 按桥型查附录B（示例：整体式板桥） │ ├─ 上部结构 LAYER γ=0.40 │ ├─ 下部结构 LAYER γ=0.40 │ └─ 附属构造 LAYER γ=0.05 │ └─ 部件（ω 权重） ├─ 桥跨 2 SPAN (spanNo=2, bridgeType=B03) └─ 桥跨 3 SPAN ...

3.1 节点类型枚举（node_type）

重要前提：node_type 只描述 bi_object 结构树节点自身的角色，与「构件」无关。构件由独立的 bi_component 表承载，通过 bi_component.bi_object_id 外键挂到树上（通常挂在 PART 或 LEAF 节点），构件自身不带 node_type。已核实：bi_object 树的末端是「面定位」节点（左侧面/右侧面/顶面/底面/倒角等，如「桥墩→盖梁→左侧面」），这些节点是结构对象叶子，不是构件，也不被 bi_component 引用。

node_type含义对应新标准概念是否绑定 γ/ω
ROOT桥梁根节点全桥—
UNIT评定单元（主桥/左幅引桥）3.1.2 评定单元绑定 bridgeType（桥型是 UNIT 级属性）
SPAN桥跨节点（新增）桥跨继承 bridgeType，γ 挂子层
LAYER结构层（桥面系/上部/下部/附属）附录B 结构部位γ 系数
PART部件（同类构件集合，如桥墩/桥台/支座）2.1.5 部件ω 权重
LEAF结构对象末端节点（面定位，如左侧面/顶面/倒角）—（树的最底层，非构件）—
LEGACY迁移前旧数据占位（ADD COLUMN 默认值）——
构件与树的边界（关键）：评定引擎取「部件最差构件标度 CI(j)=max{ECI}」时，构件的遍历范围来自 bi_component.bi_object_id 挂到某 PART 节点的集合，与 bi_object 树里 PART 之下是否还有 LEAF（面定位）层无关。因此评定计算只需 ROOT/UNIT/SPAN/LAYER/PART 五类即可闭环；LEAF 仅用于给 300 万条面定位叶子「贴标签」，避免 node_type 回填时大量节点无法归类，LEGACY 是迁移完成前的临时态（完成后不应有节点停留在此值）。
最大的坑：现有代码靠 ancestors 长度硬编码层级，加一层会全部失效。 已核实 correctAllWeights()、reassignComponentsFromOthers()、repairCountsFromSubtree() 里都有 ancestors.length - rootIndex == 2 / 3 / 4 这类判断，以及"从根算第4级为构件叶子"的隐含假设。插入 SPAN 层后所有层级都 +1，这些硬编码必须同步改为按 node_type 判断——这是方案A落地时工作量最容易被低估、也最易出回归的部分。注意：现有「第4级为构件叶子」的假设本身就不准确（构件在 bi_component 表，树里第4级实为面定位节点），改造时应一并纠正为按 node_type 判定。

4.1 计算入口改造示意（伪代码）

// 改造后：calculateBiEvaluation(taskId, rootObjectId)
List<BiObject> units = selectByNodeType(rootObjectId, UNIT);
List<BiSpanEvaluation> spanResults = new ArrayList<>();

for (BiObject unit : units) {
    List<BiObject> spans = selectByNodeType(unit.getId(), SPAN);
    for (BiObject span : spans) {
        // 1. 取该跨的四个结构层（LAYER，含γ）
        // 2. 逐层取部件（PART，含ω），部件取最差构件标度
        // 3. 算 BSCI = 100 - Σ(CI×ω×γ)/5，判跨等级
        spanResults.add(spanEvaluationService.calc(span, taskId));
    }
}
// 全桥：单跨直接取，多跨一致性判断 + 插值 BCI（3.4.2/3.4.3）
biEvaluation.setBcI(calcFullBridge(spanResults));

五、三大建模难点的落地规则

难点新标准依据方案A 落地规则
① 共用墩归属 正式稿 3.3.1 条文说明：相邻两跨共用的桥墩、支座、伸缩装置等在两跨均要计算（原依据 6.1.2"归靠墩侧"仅适用于跨内节段连接处，已修正） 共用构件两跨均计入：新增关系表 bi_span_component_part(component_id, span_id, part_id, is_shared) 支持构件多跨挂接（推荐，不产生重复构件记录、报告不重复计数）；part_id 显式锚定「该构件在此跨内所属部件节点」，服务 BSCI 求和的 CI(ij)·ω(j)；is_shared=1 标记共用构件。备选：受控复制（两条记录共享 source_id）。props_json 记 {"shared_pier":true}，前端支持人工复核。
② 全桥性构件 3.1.8 悬索/斜拉/特殊结构可制定专用评定标准 悬索桥主缆/索塔/锚碇、斜拉桥索塔等天然不分跨构件：单跨悬索桥（如宜都主桥）整桥即 1 跨，直接归入唯一 SPAN，无歧义；多跨悬索/斜拉桥走 3.1.8 出口，全桥性构件单列"全桥层"（node_type=LAYER 且挂在 ROOT/UNIT 下，不挂任何 SPAN），全桥评定时单独加权。系统保留"跨内构件 + 全桥性构件"两类标记。
③ 桥面系纵向分段 附录B 桥面系为独立结构层，每跨一套 桥面铺装等纵向连续构件按跨切分；伸缩缝/伸缩装置属相邻两跨共用构件，按 3.3.1 条文说明在两跨均要计算，用 bi_span_component_part 关系表多跨挂接（不采用"归跨号较小一侧"）。切分边界记录在构件 props；无法确定归属的标记 {"pending_confirm":true} 供人工复核。

六、历史数据迁移详细步骤

迁移是方案A最大的工作量，分六步，全程可回滚、可验证：

步骤操作关键点 / 产物
0. 备份 全量备份 bi_object / bi_component / bi_evaluation / bi_disease 四表 迁移前快照，回滚依据
1. 编码规则确认 统计现有构件 code 格式，确认跨号段位置与取值域 已核实 R-<幅>-<跨>-<序>#名称，跨号 1~9
2. 解析构件编码，确定跨号 脚本解析每条构件的 code，确定其跨号（跨号写 bi_object.span_no，不写构件表） 产出《构件→跨号映射清单》供核对
3. 生成 SPAN 节点并挂接构件 按"评定单元 × 跨数"批量生成 SPAN 节点；跨下按附录B 生成 LAYER 子层并绑定 γ；构件按跨号写入关系表 bi_span_component_part 完成挂跨 共用墩/全桥性构件按第五节规则分配，标记待人工确认项
4. 校验挂跨完整性 校验关系表中每个构件都已挂跨（全桥性构件除外），作为"迁移完成"标记 关系表无记录的构件 = 迁移遗漏，全量检查
5. 评定实体改造 新增 BiSpanEvaluation；BiEvaluation 升级为全桥汇总；计算入口改 UNIT→SPAN 遍历 旧桥幅级数据保留 deprecated，不做标度反推
6. 界面与报告 前端渲染 SPAN 层；报告按跨定位输出 BSCI/BCI 与评分引擎重写同批上线
迁移安全护栏（务必遵守）
  • 迁移脚本写成幂等——重复执行不产生重复 SPAN 节点（用 parent_id + span_no 唯一约束）；
  • 每步产出校验清单（跨数、挂载构件数、γ/ω 覆盖率），迁移后与备份表逐项 diff；
  • 先跑灰度：选一座单跨桥 + 一座多跨桥各做一遍，验证正确后再批量。

七、验证方案与风险控制

7.1 验证要点

  • 结构正确性：迁移后每跨下 LAYER 数=4（或全桥性构件单列），γ 合计=1.0，部件 ω 合计=100（整数）；
  • 计算正确性：用宜都长江大桥构造一个已知答案的手算用例，比对 BSCI/BCI 与跨等级；
  • 无遗漏：关系表 bi_span_component_part 中无记录的构件数 = 0（迁移完成后，全桥性构件除外）；
  • 回归：correctAllWeights / reassign / repairCounts 三个层级敏感方法在加层后全量回归。

7.2 风险与对策

风险等级对策
硬编码层级判断改漏导致权重/构件数错乱高全仓 grep ancestors.length 与 == 2/3/4，逐处改为 node_type 判断；加单元测试覆盖
共用墩/全桥性构件归属错误中规则自动归 + props 标记 + 人工复核入口；迁移清单逐项确认
多跨长桥 SPAN 节点数量爆炸（如 30 跨）中SPAN 节点本身轻量（只存跨号+桥型+γ），爆炸的是其下 LAYER/PART 复制——用模板引用（templateObjectId）而非物理复制，部件/构件数据按 span_id（关系表）过滤共享
与评分引擎重写（并行 P0）的耦合中跨层改造与引擎重写同批立项，但接口先定：SpanEvaluationService 只依赖 span 节点 + 部件标度，不依赖旧扣分逻辑
结论：方案A是"缺一层补一层"的最小侵入改造——复用 bi_object 树表、加 node_type/span_no/bridge_type 三列、在评定单元与结构层之间插入 SPAN 节点，使数据模型与新标准"评定单元→桥跨→结构层(γ)→部件(ω)→构件"完全同构。核心工作量集中在：①硬编码层级判断改造、②SPAN 节点生成与构件重挂迁移、③跨评定引擎（BSCI）新增三块，且三者可与评分引擎标度加法重写同批推进。历史病害数据因已存完整定量参数 + 构件编码隐含跨号，可程序化迁移，不必人工重建。
