现行实现 vs JTG/T 5230—2026 符合性核对报告

核对对象：BuildingInspector（bi-biz 评分引擎）｜ 目标：新标准 JTG/T 5230—2026（2026-11-01 实施）｜ 编制日期：2026-10-01

总体结论：现行评分引擎整体按 JTG/T H21—2011（旧规范）实现，与新标准 5230—2026 存在系统性不兼容，需重构而非修补。 评分模型、评定层级、权重体系、等级界限、病害标度四大核心全部基于旧规范，代码中多处硬编码旧规范参数。 距离新标准实施（2026-11-01）仅剩 1 个月。

本次核对的代码证据（均位于 bi-biz 模块）：
  • 构件评分：service/impl/ScoreServiceImpl.java（H21 式 4.1.1 + 表 4.1.1 扣分 + √x 递减）

  • 等级界限：ConditionServiceImpl.java:210-222 与 BiEvaluationServiceImpl.java:292-304（均硬编码 [95,80,60,40]）

三、关键代码级证据

3.1 构件评分（旧规范 4.1.1）

// ScoreServiceImpl.java:188-211 —— 严格照搬 H21 公式 4.1.1 if (i == 0) { totalDeduction = deduction; } // x=1: U₁ = DP₁ else { double sqrtX = 1.0 / Math.sqrt(i + 1); // 1/√x ... currentDeduction = (DP/100·√x) × (100−ΣU) // x≥2 递减 } finalScore = 100 − totalDeduction;

对照：新标准无此扣分/递减机制，构件改用 ECI = EDI+EFI+EAI（标度 0~5 加法）。

3.2 扣分取值表（旧规范表 4.1.1）

// ScoreServiceImpl.getDeductionValue() —— 硬编码 H21 表 4.1.1 case 3: {1→0, 2→20, 3→35} case 4: {1→0, 2→25, 3→40, 4→50} case 5: {1→0, 2→35, 3→45, 4→60, 5→100}

对照：新标准废除扣分值，改为耐久性缺损标度 EDDI(0/1/2) 与结构性缺损标度 ESDI(0/1/2/3)。

3.3 t 值字典（旧规范表 4.1.2）

// Condition.java:18-58 —— 完整硬编码 H21 表 4.1.2（n=1~200） tMap.put(1, ∞); tMap.put(2, 10.0); ... tMap.put(30, 5.4); tMap.put(40,4.9); tMap.put(50,4.4); ... tMap.put(200,2.3); public static Double getT(int n){ ... } // 未列值内插

对照：新标准无 t 值概念，部件直接取最差构件标度。

3.4 等级界限（旧规范表 4.1.5，两处硬编码）

// ConditionServiceImpl:210-222 与 BiEvaluationServiceImpl:292-304 完全一致 ≥95→1类 ≥80→2类 ≥60→3类 ≥40→4类 <40→5类

对照：新标准为 (90,100]/(75,90]/(60,75]/(40,60]/[0,40]，且按桥跨/全桥指数判定。

3.5 权重校验（旧规范表 4.2.5 固定 0.4/0.4/0.2）

// BiEvaluationServiceImpl:256-260 —— 强制上/下/桥面系权重之和=1 totalWeight = superWeight + subWeight + deckWeight; if (totalWeight != 1) throw ...("权重之和不等于1");

对照：新标准改为 19 类桥型 γ+ω 参数表，权重为整数 0~100 且含"附属构造"独立结构层（γ=0.05），不再强制三分层和=1。

五、结论

核对结论：现行实现与新标准 JTG/T 5230—2026 不相符，属于"旧规范全覆盖、新规范零覆盖"状态。 评分模型、评定层级、权重体系、等级界限、病害标度、缺损分类、功能/影响维度等 7 项 P0 项全部基于 H21—2011， 不存在可局部修补的兼容空间，需以"新引擎 + 数据重建 + 迁移方案"整体重构。 鉴于新标准 2026-11-01 实施，建议立即启动 P0 项改造立项。
